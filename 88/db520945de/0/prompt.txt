## Topic
Evaluating CLI interfaces for SQL database access suitable for embedding in a Pi package workflow, comparing Harlequin and usql.

## Key Findings
- Harlequin is a TUI/CLI application launched via the `harlequin` command, but has no documented non-interactive or "headless" query mode for scripting (`harlequin -c "SELECT ..."`); it is oriented toward interactive terminal use [4][7].
- Harlequin uses Click for CLI parsing and dynamically builds options from installed adapters; it supports config profiles (`harlequin --config`, `harlequin -P "profile"`) and can be wrapped by application frameworks (e.g., `django-harlequin`) [1][4].
- `usql` is a single-binary, cross-platform universal SQL CLI written in Go, modeled on `psql`, supporting Postgres, MySQL, SQLite, SQL Server, Oracle, and others via Go `database/sql` drivers [1][2][4].
- `usql` is explicitly designed to be scriptable and non-interactive friendly: supports running queries from files (`-f`), reading from stdin for pipelines, variable interpolation, and result export—making it suitable for embedding in automated workflows [1][4].
- `usqlgen` allows creating custom `usql`` builds with additional or alternative database drivers without forking, useful for niche backends [3].
